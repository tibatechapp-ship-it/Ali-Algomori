# ADR-0005: طبقة أمان استقبال الملفات وفصل صلاحية الاستقبال عن الصحة العلمية

- الحالة: مقبول
- التاريخ: 2026-11-22
- تكمل: [ADR-0003](0003-task-ledger-mandatory-gates.md) (بوابات المهام الإلزامية)،
  [ADR-0004](0004-first-certified-engine.md) (مسار الاعتماد المرجعي)
- تُحكم: [حوكمة البيانات](../DATA_GOVERNANCE.md) — قاعدة «الخام غير قابل للتعديل»

## السياق

قرار المالك الملزم لهذه المرحلة: «لن نعتبر نجاح CI شهادة بصحة النتائج
الجيولوجية». نجاح CI يثبت أن مسارات الكود تعمل كما كُتبت؛ لا يثبت أن بيانات
المستخدم سليمة، ولا أن ملفًا مرفوعًا آمن على استقباله، ولا — في أقصى الحدود —
أن نتائج محرك علمية صحيحة. حتى 0.4.0 كانت طبقة التحقق تبحث في سلامة بنية
الملف بعد تسجيله، لكن الاستقبال نفسه (البايتات قبل أن تصير «بيانات») كان
مفتوحًا: أي ملف بأي اسم بأي محتوى بأي حجم يمكن أن يدخل السجل.

## القرار

### 1. بوابة استقبال قبل التسجيل: `data_layer/reception.py`

كل ملف يمر عبر `check_upload()` قبل أن يصبح سجلاً في `datasets.json`. أربعة
أبعاد، لكل منها رموز رفض صريحة تُعرض كأدلة (لا رسائل سرية):

| البُعد | الحماية | الرموز |
| ------ | ------- | ------ |
| حدود الحجم | سقف لكل ملف (افتراضي 100MiB، `GEOLOGIA_MAX_UPLOAD_BYTES`)؛ الملف الزائد لا يُهشَّم حتى | `SEC_TOO_LARGE` |
| تفتيش المحتوى | قراءة البايتات السحرية لا الامتداد؛ مجهول ثنائي يُرفض؛ HTML/SVG في رفع بيانات يُرفض (خطر XSS مخزّن) | `SEC_UNKNOWN_MAGIC`، `SEC_EXT_MISMATCH`، `SEC_HTML_EMBEDDED` |
| أمان الأرشيفات | تحليل بنيوي فقط — لا استخراج لقرص أبدًا: نسبة تمدد لكل مدخل، سقف عدد المدخلات، سقف إجمالي الفك، مسارات الاجتياز، روابط رمزية، مدخلات مشفرة | `SEC_ZIP_BOMB`، `SEC_PATH_TRAVERSAL`، `SEC_ARCHIVE_SYMLINK`، `SEC_ARCHIVE_ENCRYPTED`، `SEC_ARCHIVE_CORRUPT` |
| النظافة | تعقيم أسماء الملفات (فصل مسارات، إزالة علامات bidi المخفية — خطر فعلي على منصة عربية، أسماء Windows المحجوزة، بايتات تحكم)، رفض NUL والسطور العملاقة (>1MiB) قبل أي تحليل، إبلاغ/إزالة ميتاداتا TIFF | `SEC_NAME_SANITIZED`، `SEC_NAME_REFUSED`، `SEC_CONTROL_CHARS`، `SEC_LINE_TOO_LONG`، `META_PRESENT`/`META_STRIPPED` |

ضمانات التحليل الصارم: المحتوى لا يُنفَّذ ولا يُقيَّم أبدًا — قراءة بايتات،
`struct` فقط للثنائيات، `json.loads`/`csv` للنصوص، وكل السقوف قابلة للضبط
بالبيئة لكنها معقولة دائمًا.

### 2. التحقق العلمي الموسع: المعلن مقابل الملاحظ

`validate_file()` يقبل الآن `declared_crs`/`declared_units` من سجل البيانات
ويفحص التناقض بين الإعلان والمحتوى الفعلي:

- CRS مسقط معلن (UTM) وأعمدة درجات جغرافية → **رفض** (`CRS_MISMATCH_PROJECTED_GEO`).
- CRS جغرافي معلن وقيم بمقاييس مسقطة → **رفض** (`CRS_MISMATCH_GEO_PROJECTED`).
- GeoJSON معلن بغير WGS84 → **رفض** (`CRS_GEOJSON_NON_WGS84`) — محتوى RFC 7946
  درجات WGS84 بحكم المواصفة؛ وترتيب المحاور يُسجل صراحة (`CRS_AXIS_ORDER_NOTE`).
- CRS محلي بلا تحويل مثبت → تحذير صادق (`CRS_LOCAL_NO_TRANSFORM`): غير قابل
  للإسناد الجغرافي حتى يُسجل تحويل مثبت.
- LAS وحدات معلنة تخالف مقاييس الأعماق → تحذير (`CRS_UNITS_SUSPECT`).
- لا إعلان → يُسجل كافتراض معلن (`CRS_NONE_DECLARED`) — الصمت لا يعني اليقين.

### 3. رفع شدة التلف: الملف التالف يُرفض لا يُعلَّق

`LAS_DATA_ROWS_MISMATCH` (عدد الصفوف المعلن ≠ الموجود) كان تحذيرًا — الآن
خطأ: قص الملف أو عبثه ليس «ملاحظة مراجعة». وأُضيف فحص تضارب المفاتيح
(`CSV_ID_CONFLICT`): نفس المعرف ببيانات مختلفة = إدخال مزدوج/خطأ دمج → رفض.

### 4. الفصل الجوهري الذي يفرضه قرار المالك

الطبقات الثلاث تجيب عن أسئلة مختلفة، ولا واحدة منها تختفي بعبور الأخرى:

1. **أمان الاستقبال** — «هل هذا البايت آمن قبوله وفحصه؟» (`check_upload`)
2. **صلاحية الصيغة** — «هل هذا الملف متماسك بنيوياً؟» (`validate_file`)
3. **الصحة العلمية** — «هل النتائج صحيحة؟» — **حصرياً** الاختبارات المرجعية
   المثبتة خلف بوابة `certified` (ADR-0004)، بمقارنة أعداد نسبية دقيقة مستقلة
   عن مسار floats المحرك.

حتى الأرشيف النظيف بنيوياً يعود بحالة `needs_review` لا `accepted` — لأن
محتويات أعضائه لم تتحقق بعد. لا طبقة تمنح شهادة لم تفحصها.

### 5. جسم الأدلة الثابت (corpus الرفض المرجعي)

كل حالة رفض لها ملف ذهبي في `tests/data/` (19 ملفاً) واختبار يثبت **رمز
الرفض الدقيق** — لا مجرد «فشل». المولد `scripts/make_corrupt_corpus.py`
يعيد بناءها بأسلوب محدد الخطوات، والنتائج المتوقعة موثقة في
`tests/data/README.md`. أي تغيير في السلوك يكسر الاختبار قبل أن يلمس بيانات
حقيقية.

## البدائل التي رُفضت

- **اعتماد مكتبة خارجية** (python-magic، rasterio، lasio): ينتهك قاعدة صفر
  تبعيات طبقة البيانات على Termux، ويستدعي دورة حياة طرف-ثالث كاملة قبل
  الدمج (ADR-0003/0004). التحليل البنيوي اليدوي أخف وأخضع للفحص الكامل.
- **إزالة ميتاداتا إجبارية عند الاستقبال**: تعارض قاعدة «الخام غير قابل
  للتعديل»؛ لذا المبدأ هو: الإبلاغ دائماً، والإزالة أداة اختيارية
  (`strip_tiff_auxiliary_tags`) تنتج ملفاً مشتقاً جديداً — الأصل يبقى كما هو.
- **رفض كل CRS محلي**: مبالغة — ملفات الآبار بالأعماق المحلية شرعية؛ الصحيح
  تحذير بأنها غير قابلة للإسناد الجغرافي بلا تحويل مثبت.

## التبعات

- إيجابية: 41 اختباراً جديداً (الإجمالي 147)، صفر تبعيات جديدة، رفض موثق
  بالرموز في كل نقطة، فصل الاختصاصات الثلاث صار عقداً مفحوصاً.
- تكاليف مقصودة: ملفات >100MiB تُرفض عند الاستقبال (يرفع المشرف السقف
  صراحةً وتُسجل القراءة)؛ CRS محلي يبقى تحذيراً حتى تسجيل تحويل؛ الأرشيفات
  لا تُقبل كبيانات حتى فحص أعضائها فردياً.
- غير منجز عمداً: استقبال HTTP مباشر (multipart) — الطبقة واجهة برمجية
  نقية الآن؛ ربطها بنقطة `/api/v1/uploads` عمل لاحق بعد مراجعة الأداء.
