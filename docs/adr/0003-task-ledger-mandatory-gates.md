# ADR-0003: سجل مهام ببوابات إلزامية وعزل بيئي مسبق

- الحالة: مقبول
- التاريخ: 2026-11-21

## السياق

معيار المالك الملزم: «لن نعتبر GEOLOGIA منصة جيولوجية ذكية حقيقية حتى تستطيع
استقبال بيانات حقيقية، والتحقق منها، وتشغيل محرك علمي موثق، وإظهار الأدلة
والنتائج وحدود عدم اليقين» — ولا دمج لمحركات (GemPy/MODFLOW) قبل طبقة بيانات
موثوقة واختبارات مرجعية.

## القرار

1. **سجل مجموعات بيانات دائم** (`datasets.json` تحت `GEOLOGIA_DATA_DIR`):
   كل مجموعة بهوية محتوى (`ds-` + sha256[:12])، ومصدر، ورخصة، وCRS معلن،
   وتقرير تحقق صيغي (LAS/GeoJSON/CSV/TIFF) وتاريخ تحقق البصمة.
2. **سجل مهام دائم** بحالات: `planned → inputs_validated → ready → executed →
   verified` + `rejected` للغلق الصادق.
3. **بوابات انتقال إلزامية** في الكود لا في التوثيق:
   - إلى `inputs_validated`: كل مجموعات المهمة سجلت وتجاوزت التحقق.
   - إلى `ready` أو `executed`: المحرك `certified` + إصدار مثبّت + حدود موارد
     (CPU/ذاكرة/مهلة). في مرحلة التأسيس لا يوجد محرك certified، فالتنفيذ
     **مستحيل بنيوياً** وكل محاولة تُرفض برسالة صادقة (409 عبر API).
4. **مواصفة العزل** جزء من سجل المهمة نفسها (بيئة معزولة، إصدار مثبت، حدود
   موارد) وفق سياسة الدمج — لا مهمة بلا مواصفة عزل مكتملة.
5. ترتيب البناء الملزم: اختبارات واجهة حقيقية → طبقة تحقق البيانات → نظام
   المهام والعزل → وبعد إثباتها فقط يبدأ دمج المحركات.

## العواقب

- لا يمكن لأحد — ولا للمنصة نفسها — تنفيذ مهمة على بيانات غير مدققة أو محرك
  غير معتمد؛ الرفض موثق في تاريخ المهمة.
- سجل المهمة هو بدء نظام الإثبات: لاحقاً تُضاف نتائج المحرك وحدود عدم اليقين
  إلى السجل نفسه فيصبح التقرير النهائي مشتقاً منه لا كتابة مستقلة.
