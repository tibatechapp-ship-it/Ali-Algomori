# سياسة دمج المحركات

## المبدأ

لن تُنصّب كل المحركات في بيئة Python واحدة (تعارض GDAL/NumPy/Qt/PyTorch/SciPy).
كل محرك = بيئة معزولة + Adapter + عقد موحد + سجل مركزي (Engine Registry).

## دورة حياة حالة المحرك

| الحالة | المعنى |
| ------ | ------ |
| `planned` | مذكور في السجل فقط — لا تثبيت ولا كود (الحالة الحالية للجميع) |
| `evaluated` | دُرست الواجهة والرخصة والاعتماديات ووُثقت |
| `sandboxed` | يعمل في بيئة معزولة بحدود موارد + health check |
| `integrated` | Adapter بعقد مُصدّر + اختبارات تكامل ناجحة |
| `certified` | اختبار علمي مرجعي قابل لإعادة الإنتاج + مراجعة مستقلة |

لا ترقية حالة بدون دليل موثق في المستودع.

## شروط إلزامية قبل الدمج

1. ترخيص متحقق وموثق (ورخصة كل Adapter مشتق منه).
2. إصدار مثبت (pinned) قابل لإعادة الإنتاج.
3. فحص مدخلات ومخرجات بمخططات مُصدّرة (versioned schemas).
4. حدود موارد: CPU/ذاكرة/مهلة، وإيقاف المهمة عند تجاوزها.
5. provenance كامل: بيانات، إصدار، معلمات، تحذيرات، مخرجات.
6. health check دوري.

## قواعد الادعاءات العلمية

- أرقام benchmark خاصة بنطاقها: نجاح وكيل GIS بنسبة 96% على 50 مهمة
  لا يعني دقة 96% على أي منطقة جيولوجية.
- نمذجة عدم اليقين (GemPy) لا تثبت وجود ذهب أو ماء؛ النسب تحتاج معايرة مستقلة.
- EIS Toolkit ينتج خرائط **قابلية** استكشاف، لا تأكيد موارد.
- ممنوع منعًا باتًا ادعاء تشغيل محرك لم يعمل فعليًا.

## ممنوعات

- نسخ كود طرف ثالث داخل المستودع دون مراجعة الرخصة.
- تنفيذ كود مستودعات أو ملفات مستخدمين غير موثوقة.
- تعديل البيانات الخام (تُنشأ مشتقات منفصلة دائمًا).
