# معيار القبول الملزم — GEOLOGIA

> نص معيار مالك المنصة، معلن في [ADR-0003](adr/0003-task-ledger-mandatory-gates.md) وفي اختبارات المنصة نفسها.
> **لا يُعتبر GEOLOGIA منصة جيولوجية ذكية حقيقية حتى تجتاز الخمس بوابات التالية،
> وبالترتيب، لا يُفتح أي باب منها قبل إثبات ما قبله.**

| البوابة | المعنى العملي | أين يُختبر |
| ------- | -------------- | ----------- |
| 1. استقبال بيانات حقيقية | كل مهمة تبدأ من سجل مجموعات بيانات بهوية محتوى (sha256) ومصدر ورخصة | `POST /api/v1/datasets` + اختبارات `test_data_layer` |
| 2. التحقق منها | مدقق صيغة (LAS/GeoJSON/CSV/TIFF بنيوي) + تحقق بصمة قبل أي استخدام **ولحظة التنفيذ** | `POST /api/v1/datasets/{id}/validate` + الملفات الذهبية في `tests/data/` |
| 3. تشغيل محرك علمي موثق | لا تنفيذ لمحرك إلا بعد بوابة `certified` (اختبار مرجعي مثبت قابل لإعادة الإنتاج) — الطريق الوحيد: محرك أول-الطرف بمرجع مثبت ([ADR-0004](adr/0004-first-certified-engine.md))؛ الطرف الثالث (GemPy، MODFLOW…) يبقى مرفوضاً حتى دورة حياة كاملة | `POST /api/v1/engines/{id}/certify` + بوابة `engine_certification` في `data_layer/tasks.py` + 409 |
| 4. إظهار الأدلة والنتائج وحدود عدم اليقين | تقرير تنفيذ إلزامي الحمل: مدخلات ببصماتها، صيغة واستشهادات، معلمات مثبتة، نتائج، ±1σ عدم يقين، حدود صلاحية، إخلاء — التقرير الناقص لا يسمح بمهمة `verified` | بوابة `evidence_incomplete` في `data_layer/executor.py` + `GET /api/v1/tasks/{id}/report` |
| 5. صفر هلوسة معرفية | الجواب إما مقطع مخزن باستشهاده أو «ليس في المكتبة»؛ لا توليد خارج المصادر ولا ادعاء تدريب لم يحدث | `POST /api/v1/knowledge/query` + ADR-0002 |

## ما الذي بدأ فعلاً وما الذي لم يبدأ بعد

- بدأ (0.3.0): اختبارات الواجهة الحقيقية، طبقة تحقق البيانات بمدخلات ونتائج
  مرجعية ذهبية، سجل المهام والعزل بالبوابات الإلزامية، طبقة المعرفة الاسترجاعية.
- بدأ (0.4.0): **مسار الاعتماد نفسه** — أول محرك علمي موثق معتمد
  (`porosity_density_v1`) بمرجع مثبت بجبر نسبي دقيق، تنفيذ مقفول بالأدلة مع
  كشف عبث لحظة التنفيذ، بوابة `verified` تفحص اكتمال الأدلة، و11 اختبار HTTP
  حي على خادم uvicorn حقيقي (106 اختباراً على المسارين).
- لم يبدأ بعد (مقصود): دمج أي محرك طرف ثالث (GemPy، MODFLOW 6…) — **مرفوض في
  الكود** حتى دورة حياة `evaluated → sandboxed → integrated` كاملة ثم اختبار
  مرجعي مثبت لكل محرك على حدة.
