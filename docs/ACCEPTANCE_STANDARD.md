# معيار القبول الملزم — GEOLOGIA

> نص معيار مالك المنصة، معلن في [ADR-0003](adr/0003-task-ledger-mandatory-gates.md) وفي اختبارات المنصة نفسها.
> **لا يُعتبر GEOLOGIA منصة جيولوجية ذكية حقيقية حتى تجتاز الخمس بوابات التالية،
> وبالترتيب، لا يُفتح أي باب منها قبل إثبات ما قبله.**

| البوابة | المعنى العملي | أين يُختبر |
| ------- | -------------- | ----------- |
| 1. استقبال بيانات حقيقية | كل مهمة تبدأ من سجل مجموعات بيانات بهوية محتوى (sha256) ومصدر ورخصة | `POST /api/v1/datasets` + اختبارات `test_data_layer` |
| 2. التحقق منها | مدقق صيغة (LAS/GeoJSON/CSV/TIFF) + تحقق بصمة قبل أي استخدام | `POST /api/v1/datasets/{id}/validate` + الملفات الذهبية في `tests/data/` |
| 3. تشغيل محرك علمي موثق | لا تنفيذ لمحرك إلا بعد بوابة `certified` (اختبار مرجعي قابل لإعادة الإنتاج + مراجعة مستقلة) — في التأسيس التنفيذ **مستحيل بنيوياً** | بوابة `engine_certification` في `data_layer/tasks.py` + 409 |
| 4. إظهار الأدلة والنتائج وحدود عدم اليقين | كل مخرج يحمل المصدر والإصدار والمعلمات والحدود؛ الرقم بلا طريقة استخراج لا يُعرض | حقول `matched_keywords` في الخطة، `citation` في المعرفة، تاريخ المهمة |
| 5. صفر هلوسة معرفية | الجواب إما مقطع مخزن باستشهاده أو «ليس في المكتبة»؛ لا توليد خارج المصادر ولا ادعاء تدريب لم يحدث | `POST /api/v1/knowledge/query` + ADR-0002 |

## ما الذي بدأ فعلاً وما الذي لم يبدأ بعد

- بدأ (0.3.0): اختبارات الواجهة الحقيقية (77 اختباراً على مسارين)، طبقة تحقق
  البيانات بمدخلات ونتائج مرجعية ذهبية، سجل المهام والعزل بالبوابات الإلزامية.
- لم يبدأ بعد (مقصود): دمج أي محرك علمي (GemPy، MODFLOW 6…) — **معطّل بنيوياً**
  حتى اجتياز البوابات 1-2 في سيناريو حقيقي كامل، ثم بوابة `certified` لكل محرك.
